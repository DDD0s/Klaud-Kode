fix: harden the body link after a full review of the connect slice

An independent read-only review of the connect slice plus our own pass turned
up defects that the first implementation shipped with. All are fixed here.

Correctness:
- The proxy keyed in-flight calls by the client's raw JSON-RPC id: two MCP
  sessions using the same id collided with a 503, and a late reply could be
  delivered to a new caller reusing the id. The brain now allocates internal
  ids and restores the caller's on reply.
- JSON-RPC batches and id:null requests were misclassified as notifications
  and silently dropped (202); batches now fan out and aggregate in order,
  malformed payloads get 400, and null-id requests wait for their reply like
  the Body side expects.
- The Body's brainUrl config and KLOUD_KODE_BRAIN_URL were parsed but never
  copied into Config, so only --to ever worked.
- Handler goroutines on the Body outlived their connection on the root
  context; they now run on a per-connection context with a bounded semaphore,
  a WaitGroup drain and a ping loop that notices a hung peer.
- tunnelGuard fields were read and written under different locking; the
  whole ensure() now runs under one mutex. Detach of a replaced connection
  no longer fails its successor's calls. Writing with a per-request context
  could close the shared link; writes now use a connection-scoped context.

Safety and fail-fast config:
- BodyConnect with built-in TLS listeners is refused at load, a body token
  under 24 chars is refused, a typo'd KOMPUTER_BODY_CONNECT value errors
  instead of silently reading as off, and the endpoints 404 when the mode is
  off. /body/mcp is loopback-only and shares the API auth limiter.
- The Body refuses a plaintext ws:// brain outside loopback/private ranges
  unless KLOUD_KODE_BRAIN_ALLOW_PLAINTEXT=1.
- The generated MCP config URL follows the actual listen address and scheme,
  the file is chmodded 0600 even when it pre-exists, and profile hostnames
  are validated so a crafted profile cannot inject lines into /etc/hostname.

Smaller: Retry-After in connect mode no longer overstates the wait, backoff
clamps at 30s with jitter and only resets after a link lived 10s, refused
flag values (--out/--profile/--root with no value) error instead of using the
boolean placeholder as a filename, closes are CloseNow so replacement does
not stall on a dead peer, and two SETUP passages are back in order.

Tests: config validation, same-id concurrency, batch round trip with id
restoration, stale-generation flush, guard concurrency under -race on Linux
CI, plaintext rejection, MCP URL from listen addresses, plus live end-to-end
runs of a connected Body executing real commands, including a batch of two
requests sharing one client id.
