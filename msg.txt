fix(body): stop losing command output to the wait race

`RunCommand` used StdoutPipe/StderrPipe and drained them from goroutines after
`cmd.Wait()`. On a loaded machine (the Linux CI runner, under -race) a fast
command can exit before the reader is scheduled, so the captured stdout is empty
even though the exit code is 0. main went red on
TestBodyRunCommandAndProcesses with ExitCode 0 and empty output.

The collectors are now the command's writers, which makes cmd.Wait also wait for
the copy goroutines, and HeadAndTail implements io.Writer with a mutex because
stdout and stderr are copied concurrently.

Two regression tests: concurrent writes stay bounded and race-free, and 40 runs of
a fast command must always capture their output.
